# Development log — 2026-10-12

## Objective

NESPICO is a low-cost **USB Famicom cartridge dumper and live-cartridge console**. A YD-RP2350A Zero and 74-series logic interface with a genuine 60-pin cartridge. The RP2350 emulates CPU/PPU/APU and accesses physical PRG/CHR buses during play; the PC or Mac receives video/audio and supplies controls.

We also want to reproduce the Tennis-to-Super-Mario-Bros. World 9 cartridge trick by preserving motherboard RAM across RESET. Automatic hot-swap detection is not part of the goal; electrical safety during cartridge exchange remains unresolved.

## Decisions made

- Keep the inexpensive **YD-RP2350A Zero** as the initial MCU; prefer 74-series parallel latches/buffers to reduce required GPIO.
- Do not add FPGA, HDMI Shield or wireless to Rev.A.
- Prioritize separate CPU and PPU bus timing, mapper writes, IRQ, and CIRAM.
- Host receives output via USB Full Speed; raw 256x240, 60fps video is too large, so a more efficient protocol is required.
- Produce only **two prototype PCBs** after software and electrical feasibility are established.

## Implemented so far

- `nespico/sim.py`: approximate NTSC CPU and PPU request schedules, configurable bus transaction deadline model, partial MMC3 A12 filter, RAM-retaining reset model and nominal USB budget check.
- `nespico/pipeline.py`: request-production cost model with no lookahead.
- `nespico/cli.py`: timing simulation command.
- Three test modules with **21 regression tests**; the previously reported local Python run passed 21/21.
- GitHub Actions workflow for Python 3.10/3.12 and stress tests, but its successful execution has **not been confirmed**.
- [Simulation results](../benchmark-results.md) and [architecture assumptions](../architecture.md).

## Results

A synthetic 262-scanline frame currently generates **29,781 CPU** and **40,488 PPU** requests. At 150 MHz, with a *hypothetical* 12-cycle transaction plus 22 ns settling, 320 ns CPU and 180 ns PPU deadlines:

| Scheduler | Missed deadlines |
| --- | ---: |
| Independent CPU/PPU bus engines | 0 |
| Shared engine | 13,496 |
| Shared engine with 10-cycle transactions | 0 |

Adding CPU/PPU address preparation time to the simulation exposes a substantial risk: a quick GPIO/PIO transaction is not enough if software cannot produce its inputs on time. The current assumptions are **not hardware measurements**, and the synthetic trace does not represent every actual cartridge, PPU, or CIRAM access.

## Not done

No real PIO assembly, RP2350 timing measurement, validated 27-GPIO pin assignment, complete 60-pin schematic, electrical safety review, MMC3 emulation, physical dump, playable cartridge, verified USB streaming, or World 9 demonstration exists yet.

## Decision / next step

**Continue simulation and PIO firmware, but do not order the two PCBs yet.** First implement a real PIO transaction sequencer and measure instruction cycles, FIFO starvation, simultaneous CPU/PPU signals and USB interference on the available RP2350A Zero.
